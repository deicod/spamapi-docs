# Security policy

## Supported versions

Security fixes target the current `main` branch. Deployments should use the
latest reviewed revision of `main`; older revisions and experimental branches
do not receive separate security backports. This policy covers the SpamAPI
service, dashboard, and WordPress plugin.

## Reporting a vulnerability

Report suspected SpamAPI vulnerabilities through the
[private vulnerability reporting form](https://github.com/deicod/spamapi-docs/security/advisories/new).
Sign in to GitHub to submit a report. Reports are private to the reporter and
maintainers handling the advisory.

Include the affected component and version, impact, reproduction steps, and a
minimal proof of concept using synthetic data. Never send live API keys, tokens,
payment details, or customer content. Coordinate disclosure with maintainers
after a fix is available, and keep exploit details out of public issues and PRs.
