API Reference¶

Public API (API Key)¶

Base path: /api/v1

Method Path Description
POST /verify-key Validate API key
POST /check Check content for spam
POST /submit-spam Report false negative
POST /submit-ham Report false positive
GET /usage Monthly usage summary
GET /sites Sites using the key

Public API Responses¶

Both feedback endpoints return HTTP 200 with a JSON acknowledgement:

{"status": "ok"}

GET /api/v1/usage returns the current month's quota and usage. percentage is a decimal string; resets_at is a UTC timestamp; throttled indicates that the account has reached its quota. A paid plan's quota applies until its subscription ends, including the rest of a paid period after cancellation; the account then uses the Free quota.

{
  "limit": 100,
  "used": 12,
  "percentage": "12.00",
  "resets_at": "2026-11-01T00:00:00Z",
  "throttled": false
}

GET /api/v1/sites returns sites, total, limit, and offset. Each site contains site, api_calls, spam, ham, missed_spam, false_positives, first_seen, and last_seen. Pagination defaults to 50 sites and is capped at 100 per request. The dashboard's sites endpoint uses its own response schema.

Dashboard API (Session)¶

Base path: /dashboard/api

Method Path Description
GET /account Get account
PATCH /account Initiate email change
GET /api-keys List keys
POST /api-keys Create key
DELETE /api-keys/{id} Delete key
GET /usage/summary Usage summary
GET /usage/history Usage history
GET /sites Sites stats
GET /billing/subscription Subscription
POST /billing/checkout Checkout session
POST /billing/portal Billing portal

Authenticate with Authorization: Bearer <session-token>, using the token returned by registration or login. Account responses wrap the current user in user. Changing the account email requires both email and the current password; the response still contains the current email until confirmation.

Creating a key returns HTTP 200 with key (the full credential, shown only once) and api_key (its metadata). Listing keys returns a keys array; deleting a key returns HTTP 204 with no body.

Usage history returns a history array with month, spam_checks, spam_detected, ham_detected, submit_spam, and submit_ham. The lookback defaults to six months and is capped at 24. Subscription details are wrapped in subscription. While a canceled subscription remains active, cancel_at gives its scheduled end and status is unchanged; it is absent otherwise.

Checkout requires plan, success_url, and cancel_url; the billing portal requires return_url. Redirect URLs must use the application's origin (https://spamapi.de for the hosted service). Both endpoints return url.

Auth API¶

Base path: /auth

Method Path Description
POST /register Register
POST /login Login
POST /logout Logout
GET /me Current user
POST /verify Verify email
POST /confirm-email-change Confirm email change
POST /forgot Forgot password
POST /reset Reset password

Registration returns HTTP 201; login returns HTTP 200. Both return user, token, and session. GET /auth/me returns user and session, and logout returns HTTP 204 with no body.

Email verification and email-change confirmation accept token and return user. Forgot-password accepts email and returns HTTP 202 with {"status":"email_sent"}. Reset-password accepts token and new_password and returns the user object directly.

Error Format¶

The public and dashboard APIs use the following JSON error format. Auth handlers return a JSON error string; their rate limiter and the dashboard session middleware can return plain-text errors.

{
  "error": "invalid_api_key",
  "message": "Invalid API key",
  "request_id": "req_123"
}

POST /api/v1/check returns HTTP 503 with error code detection_unavailable when the selected classifier fails or times out. This error carries no spam decision, score, or recommendation. Failed classifications do not increment classification usage or update site statistics. See troubleshooting for how to handle this response.
